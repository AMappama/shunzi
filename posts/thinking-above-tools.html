思维逻辑在工具之上

08.23.26 · Shunzi

项目：industry-select-product —— 选销易，工业零部件选型。微信小程序给工程师选型号、出图纸和订货单，NestJS 提供接口，Vue 做运营后台。

我从这一天里带出来的判断，先写在这里。

这一天更像一次逆向实验。桌上是一款已经做完的工业选型产品，我想从它被做成的样子里，摸到制作时的底层思维。怎么把页面抄像，我没有打算沉淀成一套做法。

工具之上是方法，方法之上是习惯，习惯之上是思维逻辑。 思维逻辑一旦站住，习惯会自己长出来；习惯稳住之后，方法才会在大量坚持里自己现身。这一天要站住的思维逻辑，落点是选型作业，所以它先对准产品结构；语法要等结构说完，才有位置。要把结构交给后面的工具，语言就得写成规格说明书。闲聊到不了施工那一步。

上一件让我把全栈跑通的，是 MedRWA Console。医疗应收进去，认购、回款、对账出来，代码几乎同样是 AI 写的。那时我从工具那一层起步：先选栈，再让页面能点、接口能通。链路跑完，我才撞上更硬的一笔——金额对了，打款方却可能对不上。程序在交付，我对这件事本身说得太少。

选销易这一天，我拿现成的产品倒着走。下面几个场面仍落在那四层上，对照的是我自己的上次和这次。实验要带走的，是制作时怎么想；仓库能跑，只是这条思路被核对过一遍。

先站住的，是思维逻辑

打开选销易的时候，我还没有那三问。轮播、分类、加购、收藏都在，货架上躺的是工业零件，我以为自己在看一个店。衣服出穿搭，化妆品出妆容，零件出配套，这个形式我见过，所以新东西好像不多。

动手之前，我还是先停了一下，问了三件很笨的事：微信小程序是什么，SaaS 能不能塞进去，包体积卡的是哪一条线。小程序是微信在 iOS / Android 上再包的一层；SaaS 能进去的是移动前端，后端仍在云上；压缩包有上限，和手机占了多少空间、运行时吃多少内存，要分开算。问完之后，平台替它托管什么、什么会被卡死，我心里有了数，这才敢碰屏幕。

这一停，站住的是思维逻辑：先确认世界的规则，再进入这个世界里的某一个东西。习惯和方法都还没有。MedRWA 那一次，我最先问出口的是怎么搭；这一次，我最先问的是它受哪些规则约束。

店这个比喻，在公式那里断掉

思维逻辑站住之后，我开始用汉语拆屏，每屏只写四件事：人来这里要做完哪一项作业，什么进、什么出，后台得备什么，这一步搁在整条链的哪一截。目录、详情、加购都还很像店，这个比喻撑了很久。若到此收笔，我会交出一份电商拆解，语法教程也可以接着写，只是产品结构还没有露面。

下一屏是齿条齿轮。水平还是垂直，载荷、速度、加速度填进去之后，纸上多出一行 F = μmg + ma。力再乘安全系数，拿去对库。目录里我做的是查，这一屏我做的是算。衣服配错，最多不好看；这里配错，轴对不上，齿也承不住。WXML 换一套写法，公式还在。语法帮不上这一屏的忙。

我这才看见货架下面那项更老的作业：翻样本、对参数、校核工况、定型号、要图纸、开订货单。微信只是把现场换到了手机上。若把页面全部换皮，工况算法、文件引擎、电机库和型号规则还在，产品就还在；这四样动了，产品才换了。逆向的对象在这里从语法挪到了产品结构上。

你对着一个做得像电商的东西时，也可以停在这一问：我拆的是货架，还是货架下面那个人离开屏幕后必须做完的事？

习惯是先把话说成规格

产品结构一旦露面，手就会反复做同一件事：继续用母语写，写到另一双手可以按着施工。选型记录不回头查产品库，而抱着成交当时的参数，因为主数据会变，成交得留下自己的时间切片。订货单当场生成，图纸按型号去找已经躺好的文件，三视图继续用图。这些细节不是技术清单，它们是规格自己长出来的枝节。

中午，文档和 ER 已经在桌上。下午，三端按文档铺开，骨架很快，因为作业已经被说完。语言在这里不是闲聊，是规格说明书。习惯就是这样长出来的：先说清楚，再调用工具。TypeScript 会不会，管的是谁敲键盘。

若你也把一天交给 AI，可以看一眼自己的聊天记录：发出去的第一句是帮我写页面，还是先把这件事说成另一人能接着做的规格？

眼前的问题，还算不上方法

晚上两件事找上门的时候，我并没有一套现成的做法。真机打不开电脑上的地址，因为手机和电脑各是各的；隧道递出去以后，接口地址和图片地址还得一起改，改漏一边，图是裂的。本地库原本可以是 SQLite 或 MySQL，可小程序要落到腾讯云的个人免费版上，那一层只给 PostgreSQL，于是整条线换成了 PG。

我完全不知道下一秒还会冒出什么。当时只想把眼前的卡住解决掉，于是去问 AI。坑过了，选型作业没有重写，中午的文件也不用推倒。下一次手机连不上、云只给某一种库，这一套还能不能用，我答不上来。它还停在摸着石头过河，算不上方法。开头那句写过：方法要在大量坚持里才现身。这一天只有一次，坚持还没开始。

手边留下的痕迹

实验要找的是制作时的底层思维。连手机、换库时摸到的几条，只是手边的痕迹，换一个项目也许还认得，却不是这一天要沉淀的抄法：

  1. 数据访问留两种姿势。 库在自己手里，走 pg 协议直连（PgClient）；库在云手里、拿不到直连地址，走云 API（CloudBasePgClient）。上层只认同一个接口，换姿势，不换调用。
  2. 不支持的，自己补。 云 API 不吃参数化绑定，就把 $n 占位符先转义成字面量再发出去。缺哪块补哪块，不等官方。
  3. 两处地址一起改。 隧道给接口递了新地址，图片地址还指着旧的，图就裂了。接口通了不算完，资源地址要跟到同一处。
  4. 成交留快照。 选型记录存成交当时的参数，不回头查产品库——主数据会变，成交得留下自己的时间切片。

这四条能让下一次少绊一跤。它们解释不了选销易为什么被做成这样。

若把 TypeScript 从这一天里抽走，剩下的仍是那三问、那一行公式、以及说完就能施工的规格。

仓库在这里：industry-select-product。思维逻辑和习惯先在了；方法还在等下一次同样的坑。下次再拆一款成熟产品，可以先问自己：我在找它的制作思维，还是在攒一份复刻手册？
